# BioVoid v0.1.0 Release

## Release Type

This is a source-only public release of a local computational research
prototype. It packages the application code, tests, reproducible configuration,
and conservative technical documentation. It does not distribute structures,
databases, models, generated reports, or benchmark artifacts.

## What This Release Establishes

- The canonical engineering path is prepared full-heavy-atom static analysis.
- Motion-aware NMA output is reported as experimental evidence and cannot alter
  the canonical static ranking.
- Run manifests, input/configuration hashes, detector versions, scoring
  contracts, and environment identity are part of the local provenance model.
- The React/Vite application is the primary local interface; the legacy
  `/portal` URL redirects to the canonical root.
- Public CI checks source hygiene, Python behavior, API contracts, and frontend
  behavior without downloading real structures or starting heavy analyses.

## What It Does Not Establish

- No discovery, binding, druggability, or success-probability claim.
- No claim that the motion-aware path outperforms static analysis.
- No sealed benchmark result or external scientific validation.
- No clinical, diagnostic, or drug-development use.

## Verification Record

The sanitized release baseline is expected to pass:

```text
python scripts/check_public_hygiene.py --history --history-ref HEAD
python scripts/check_versions.py
python -m pytest tests/ -q
cd frontend
npm run lint
npm run test
npm run build
npm run test:e2e
```

The real-PDB scientific suite is intentionally opt-in. Public CI uses the
source-only scientific invariants; local structure data must be supplied by
the operator and is never committed.

The history command is a release gate for a sanitized release ref. It is not a
claim that an unsanitized development ref or the current remote history passes
that gate.

## Reproducibility Boundary

Inputs, Atlas databases, models, raw structures, generated outputs, caches,
and private planning files stay outside the public repository. A future
benchmark or publication release must provide its own versioned manifest and
data-access instructions rather than expanding this source repository’s
boundary.
